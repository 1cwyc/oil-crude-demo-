# 事件海水密度匹配模块 PRD

> 状态：设计已实施、CLI已交付；真实数据验收仍待 accepted events 输入。下游 voyage/network 不属于本模块，未在此分支实现。
>
> 目标：为已接受的原油装载、卸载事件生成 SCPC 直接使用的海水密度，在不损失宏观航次覆盖的前提下引入月度盐度和海面温度差异。
>
> 权威边界：本文是 `event_density_matcher` 的独立规格；现有 v0.2 总体规格中关于“固定密度配置”的描述由本文取代。

## 1. 任务分级

### 1.1 不做就无法满足当前精度要求

- 核验 ERA5 与 WOA23 的变量、单位、坐标、月份和缺测值。
- 为接受事件确定唯一代表位置和 UTC 月份。
- 在 75 km 内分别选择最近的有效盐度与海温格点。
- 复用 TEOS-10 计算密度，并在缺测时回退到 `1025 kg/m³`。
- 生成能被航次模块分别按装载、卸载事件连接的最小结果表。

### 1.2 有明显收益但保持轻量

- 在 manifest 中报告实际计算和固定回退的数量。
- 在整月验收中比较时变密度与全程固定 `1025 kg/m³` 对总货量的影响。
- 对环境数据执行一次运行前 schema gate，避免单位或月份错误被静默接受。

### 1.3 当前不实施

- 逐三小时位置或全分辨率位置计算密度。
- 小时级海温、潮汐、风浪、垂向盐温剖面和吃水深度积分。
- 全球月度密度网格预计算和长期缓存。
- 双线性插值、复杂海岸线插值、Dask 和并行 NetCDF 读取。
- 将盐度、海温、匹配距离或 TEOS-10 中间量写入正式逐事件表。

## 2. 已核实事实、设计判断与待验证项

### 2.1 已核实的数据事实

ERA5 数据已经覆盖 `2025-07` 至 `2026-06`：

- 两个 NetCDF4 文件，每个包含连续六个月。
- 变量为 `sst`，单位为 K。
- 时间坐标为 `valid_time`，12个月连续且无缺月。
- 网格为 `721 × 1440`，纬度 `90` 至 `-90`，经度 `0` 至 `359.75`，分辨率 `0.25°`。
- 文件元数据表明它是 ERA5 月平均产品，而不是小时产品。

WOA23 数据包含1月至12月的完整月度气候态：

- 12个 NetCDF4 文件，每个文件对应一个自然月。
- 变量为 `s_an`，即客观分析的实用盐度，单位为 `1`。
- 网格为 `720 × 1440`，经纬度分辨率 `0.25°`。
- 表层的实际深度中心为 `1.25 m`，层边界为 `0–2.5 m`，不是严格的0 m单点。
- 时间代表 `1991–2020` 月度气候平均，不是研究期逐年实况盐度。

沿岸抽样表明，普通最近网格可能落在陆地掩膜；代表性港口的最近有效格点通常为数公里至约31 km，个别沿岸位置约51–53 km。因此必须执行“最近有效海格点”搜索，不能只取坐标轴上的普通最近单元。

### 2.2 已验证的依赖事实

- `xarray + h5netcdf` 可以读取当前 NetCDF4 文件以及 Windows 中文路径。
- `netCDF4-python` 在当前 Windows 中文路径下实测打开失败，因此第一版不采用。
- `GSW-Python 3.6.19`、`xarray 2024.11.0`、`h5netcdf 1.4.1` 和 `h5py 3.12.1` 已与仓库现有 `numpy 1.26.4` 完成兼容性读取测试。
- WOA23 使用 `decode_times=False` 打开；月份由文件名和运行前合同确定，不引入 `cftime`。

### 2.3 设计判断

- 月度环境数据足以服务月度原油贸易网络，不需要小时级密度。
- 密度只在装载、卸载两个端点使用，不需要覆盖完整航迹。
- 75 km 搜索兼顾沿岸格点缺测与空间代表性；超过该范围继续搜索可能跨越不同水团。
- 固定密度回退造成的误差小于删除完整航次造成的宏观货量漏估。

### 2.4 实施后才能核实

- 实际接受事件中 `teos10` 与 `fixed_1025` 的比例。
- 时变密度相对固定密度对月度、全期货量的实际影响。
- 个别河口、内海和高纬港口是否集中触发回退。

## 3. 模块职责与边界

模块名：`event_density_matcher`。

唯一职责：为每个已接受装载或卸载事件生成一个最终海水密度。

本模块不负责：

- 识别装卸事件；
- 计算事件代表位置；
- 判断原油船或原油航次；
- 配对装载、卸载事件；
- 计算 SCPC 货量或执行 DWT 上限封顶；
- 修改任何上游事件、AIS 或环境源文件。

## 4. 输入合同

### 4.1 已接受装卸事件

输入表：`events/loading_unloading_events`。

只读取：

| 字段 | 类型 | 规则 |
|---|---|---|
| `event_id` | VARCHAR | 非空且唯一 |
| `event_status` | VARCHAR | 只处理 `accepted` |
| `event_start_s` | BIGINT | UTC epoch 秒 |
| `event_end_s` | BIGINT | 必须大于 `event_start_s` |
| `event_longitude_deg` | DOUBLE | WGS84，可空；无效时触发固定密度 |
| `event_latitude_deg` | DOUBLE | WGS84，可空；无效时触发固定密度 |

事件代表位置由上游事件模块计算：使用事件时间窗内低速、有效三小时位置的经纬度中位位置，并选择距该中位位置最近的真实有效样本作为最终坐标。密度模块不得重复扫描三小时轨迹重新定义位置。

事件月份定义为事件时间窗中点所在的 UTC 月份：

```text
event_midpoint_s = floor((event_start_s + event_end_s) / 2)
```

不将事件月份重复保存到密度结果表。

### 4.2 ERA5 月平均海面温度

必要合同：

- 变量：`sst`。
- 单位：`K`。
- 坐标：`valid_time`、`latitude`、`longitude`。
- 研究期月份：`2025-07` 至 `2026-06`，每月恰好一个时间片。
- 经度范围：`[0,360)`；纬度可以递增或递减，适配器必须从坐标值判断。

### 4.3 WOA23 月度表层盐度

必要合同：

- 变量：`s_an`。
- 标准名：`sea_water_practical_salinity`。
- 单位：`1`。
- 坐标：`lat`、`lon`、`depth`。
- 每个自然月恰好一个文件。
- 表层深度中心为 `1.25 m`，边界为 `0–2.5 m`。
- 以月份气候态匹配事件月份，不声称是2025或2026年的实况盐度。

### 4.4 主机配置

真实文件路径位于仓库外，只通过未版本化的主机配置传入。仓库不得提交环境数据、绝对用户路径或生成结果。

## 5. 匹配与计算规则

### 5.1 运行前 schema gate

正式计算前一次性检查：

1. ERA5研究期12个月是否连续且唯一。
2. WOA23自然月1–12是否齐全且唯一。
3. 变量名、坐标、单位和维度是否符合第4节。
4. 坐标是否单调，网格是否覆盖全球。
5. 输入文件能否由配置的 `h5netcdf` 后端打开。

月份缺失、单位错误、变量缺失或文件损坏属于数据集级错误，阻断模块；不得把整批下载错误静默解释为逐事件回退。

### 5.2 空间搜索

盐度和海温独立搜索：

1. 将事件经度转换到对应数据源的经度范围。
2. 由0.25°网格索引得到事件周围的有限候选窗口。
3. 排除缺测、非有限值和超出宽松物理范围的格点。
4. 对候选格点计算球面距离。
5. 仅保留距离不大于 `75 km` 的候选。
6. 选择距离最小者；距离相同时依次按纬度、经度排序，保证确定性。

两个数据源可以选择不同的最近格点。正式结果不保存源格点和距离；算法、输入哈希和统计摘要进入 manifest，可通过相同输入重算。

### 5.3 宽松物理范围

范围仅用于识别文件错误和极端插值异常，不用于精细海洋学筛选：

```yaml
salinity_valid_range: [0, 50]
sst_valid_range_c: [-5, 47]
```

### 5.4 TEOS-10 计算

当盐度和海温均在75 km内匹配成功时：

```text
SP = WOA23 practical salinity
t  = ERA5 sst - 273.15
p  = 0 dbar

SA  = gsw.SA_from_SP(SP, p, event_longitude_deg, event_latitude_deg)
CT  = gsw.CT_from_t(SA, t, p)
rho = gsw.rho(SA, CT, p)
```

`SA`、`CT`、`SP` 和 `t` 均为运行时中间量，不写入正式表。

若最终密度不是有限数或超出宽松范围 `[990,1050] kg/m³`，该事件使用固定密度回退。

### 5.5 固定密度回退

以下任一条件触发：

- 事件代表经纬度为空或越界；
- 75 km内没有有效盐度；
- 75 km内没有有效海温；
- 盐度或海温超出宽松物理范围；
- TEOS-10计算失败或密度结果异常。

回退结果：

```text
seawater_density_kg_m3 = 1025
density_method = fixed_1025
```

回退不删除事件和航次。

## 6. 输出合同

输出表：`environment/event_seawater_density`。

主键：`event_id`。

| 字段 | 类型 | 非空 | 作用 |
|---|---|---:|---|
| `event_id` | VARCHAR | 是 | 连接装载或卸载事件 |
| `seawater_density_kg_m3` | DOUBLE | 是 | SCPC直接使用的最终密度 |
| `density_method` | VARCHAR | 是 | `teos10` 或 `fixed_1025` |

不增加质量位、盐度、海温、匹配距离、事件月份、压力、源文件、绝对盐度或保守温度字段。

模块级 manifest 至少记录：

- `run_id`、模块名和算法版本；
- 事件输入指纹；
- ERA5、WOA23文件清单与内容哈希；
- 配置哈希和 GSW 版本；
- 输出路径与行数；
- `teos10` 和 `fixed_1025` 的数量；
- 生成时间。

## 7. 下游接口

`voyage_builder` 对同一密度表连接两次：

```text
load_event_id   -> rho_load
unload_event_id -> rho_unload
```

SCPC 使用：

```text
cargo_t =
  (rho_load   * L * B * loaded_draught  * Cb
 - rho_unload * L * B * ballast_draught * Cb) / 1000
```

密度模块不保存 `rho_load`、`rho_unload` 或 `cargo_t`，也不执行用户已经确认的“估算货量超过名录 DWT 时按 DWT 封顶”；这些属于航次模块职责。

## 8. 技术方案与复用边界

### 8.1 依赖

第一版固定使用：

```text
numpy==1.26.4
pandas==2.2.3
xarray==2024.11.0
h5py==3.12.1
h5netcdf==1.4.1
gsw==3.6.19
```

选择依据：

- `xarray` 管理带标签的 NetCDF 坐标与缺测值。
- `h5netcdf/h5py` 读取 NetCDF4/HDF5，并已验证兼容中文路径。
- `GSW-Python` 直接复用 TEOS-10 C实现的 NumPy ufunc 封装。
- 上述版本已与仓库现有 NumPy 1.26.4完成只读兼容性测试，不升级到 NumPy 2。

开源实现依据：

- [pydata/xarray](https://github.com/pydata/xarray)：带标签的多维数组和 NetCDF 数据访问。
- [h5netcdf/h5netcdf](https://github.com/h5netcdf/h5netcdf)：基于 h5py 的 NetCDF4/HDF5 接口。
- [TEOS-10/GSW-Python](https://github.com/TEOS-10/GSW-Python)：基于 GSW-C 的 TEOS-10 Python 实现。

### 8.2 性能设计

- 先按事件月份分组。
- 每个月的 ERA5时间片和 WOA23文件只读取一次。
- 月内所有事件复用已加载的坐标和有效值掩膜。
- 只搜索事件周围的有限网格窗口，不扫描全球网格寻找每个最近点。
- 单进程顺序读取环境文件；不引入 Dask 和多线程 NetCDF 读取。
- 事件规模仅为航次端点，预计远小于三小时 AIS 样本数。

### 8.3 目录建议

在实施前再次检查现有公共配置、manifest、Parquet写入和CLI入口，能复用则不新增同类工具。新增业务边界建议为：

```text
ais_tanker_pipeline/environment/
├─ __init__.py
├─ sources.py                # ERA5/WOA23固定合同读取与校验
└─ event_density_matcher.py  # 事件分组、最近格点、GSW和回退

configs/environment/
└─ density.example.yaml

tests/
└─ test_event_density_matcher.py
```

不得建立通用环境数据框架、缓存服务或第二套manifest/配置系统。

### 8.4 计划入口

实现后的公开入口：

```text
python -m ais_tanker_pipeline.environment.event_density_matcher --config <host-config.yaml>
```

入口只写本模块输出目录，不能修改事件表和环境源文件。

## 10. 错误处理

### 10.1 阻断模块

- 研究期月份不完整或重复；
- 必要变量、坐标或单位不符合合同；
- NetCDF文件无法读取；
- 接受事件 `event_id` 重复；
- 事件时间区间非法；
- 输出主键重复、行数不守恒或密度为空。

### 10.2 逐事件回退

- 事件位置无效；
- 75 km内缺少任一环境变量；
- 单个环境值或TEOS-10结果异常。

逐事件回退只改变该事件的 `density_method` 和密度，不影响其他事件。

## 11. 测试驱动开发要求

在生产代码前先建立小型合成 NetCDF 和事件夹具，覆盖：

1. 事件中点正确映射 UTC 月份。
2. ERA5 `[0,360)` 与 WOA23 `[-180,180)` 经度转换正确。
3. 多个有效格点时选择球面距离最近者。
4. 距离等于75 km时允许匹配，超过75 km时回退。
5. 盐度缺失、海温缺失和两者缺失均回退1025。
6. 事件位置无效时回退1025。
7. 已知 `SP/t/lon/lat` 输入得到预期TEOS-10密度。
8. 异常环境值和异常密度触发回退。
9. 只处理 `accepted` 事件。
10. 输出一事件一行、三字段非冗余合同和重复运行确定性。

测试不得读取或提交真实环境数据；合成文件在测试临时目录中生成。

## 12. 真实数据验收

密度模块验收：

- 输出行数等于已接受装卸事件数；
- `event_id` 重复数为0；
- 密度 NULL 数为0；
- `density_method` 只包含两个允许值；
- `teos10 + fixed_1025` 数量等于输出总数；
- 报告实际密度的最小值、中位数和最大值；
- 报告固定回退的数量和比例。

与航次模块联合验收时，额外生成但不落入正式字段的对照报告：

- 使用时变密度的全期、逐月货量；
- 所有事件固定为1025时的全期、逐月货量；
- 两种口径的绝对差和相对差。

该比较用于证明环境密度修正的影响，不用于强行校准 AIS 货量到包含管道运输的国家官方总量。

## 13. 风险与控制

| 风险 | 影响 | 控制 |
|---|---|---|
| WOA23是气候态而非研究期实况 | 盐度不反映具体年份异常 | 在论文和manifest中明确口径；不声称逐日精度 |
| 沿岸格点缺测或离港区较远 | 局部密度代表性下降 | 最近有效海格点限于75 km；否则固定1025并保留航次 |
| 月平均SST平滑短期变化 | 单事件密度存在小偏差 | 研究目标为月度宏观网络，不引入小时数据 |
| 固定回退掩盖局部环境差异 | 少量事件精度降低 | 报告回退比例；不把回退解释为实测 |
| 中文路径兼容性 | 库可能无法打开文件 | 使用已实测的 `h5netcdf` 后端；路径仍由主机配置管理 |
| 依赖升级导致 NumPy 冲突 | 破坏现有流水线 | 固定已验证版本；不升级到 NumPy 2 |

## 14. 交接要求

另一台电脑运行前必须：

1. 从 GitHub任务分支或合并后的 `main` 获取代码，不能复制未提交代码包。
2. 使用自己的未版本化主机配置填写环境数据和事件路径。
3. 先运行 schema gate，再运行密度匹配。
4. 保存 manifest 和验收报告，但不得提交真实数据或生成结果。
5. 若真实事件尚未生成，只能运行环境数据检查和合成测试，不能宣称整月密度匹配已经验收。

## 15. 已确认决策

- 研究目标是宏观原油运载量估算，不追求单事件海洋环境的过度精细化。
- 搜索半径为75 km，不采用300 km远距离匹配。
- 多个有效格点时选择球面距离最近者。
- 任一环境变量缺失时整体回退到 `1025 kg/m³`，不删除航次。
- 事件位置取低速有效三小时样本的中位代表位置。
- 正式密度表只保留 `event_id`、最终密度和计算方法三个字段。
- 盐度、海温、匹配距离和质量原因只用于运行时与汇总报告，不逐事件落盘。
