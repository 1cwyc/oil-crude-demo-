# AIS 油轮三小时采样技术说明

## 1. 可迁移性边界

发布包包含流程代码、既有 AIS DuckDB 解码器、配置、安装脚本、小型验证数据和测试。接收方不需要原作者的
桌面项目目录，但仍需 64 位 Python 3.11、足够的磁盘空间和读取原始 AIS 数据的权限。原始 AIS 数据没有打包。

相对路径以 JSON 配置文件所在目录为基准解析；绝对路径保持不变。输入和输出路径只保存在配置中，算法代码不写死盘符。

## 2. 数据流

```text
STA .dat
  -> 复用 _static_query 直接解码
  -> 每日静态分片
  -> 年度 vessel_registry
  -> 年度 tanker_registry

POS .dat + tanker_registry
  -> 复用 _position_query 直接解码并 JOIN
  -> 每日 tanker_positions
  -> 每艘船/每个三小时目标的最近有效点
  -> samples_3h Parquet
  -> 可选 CSV / 网格密度 PNG
```

原始 `.dat` 是 `~` 分隔的已解析字段。DuckDB 的向量化 CSV 读取器直接扫描文件，避免逐行 Python 解析和全量
中间文件。年度处理按文件顺序执行，避免多个 30 GB 文件同时争用磁盘。

## 3. 油轮登记

2025-07-15 技术试验按用户要求纳入 80–89 全部船型码，识别策略仍为 `any_observed`：某 MMSI 在有效静态记录中只要一次出现
这些候选码，就进入年度油轮登记。正式研究仍需按数据提供方编码说明核验 85–88。登记表同时保存出现过的船型列表、冲突标记、首次/末次静态时间和最新非空元数据，
便于后续检查同一 MMSI 的船型冲突。

当配置只包含一天 STA 时，登记表只覆盖“当天曾发送有效静态船型”的油轮，可能漏掉当天有位置报文但没有静态报文的油轮。
因此 2025-07-15 配置仅用于技术试跑；“当天全部油轮”需要更宽静态时间窗或预先完成的年度登记表。

ShipType 只说明船舶类别，不等于某航次实际装载石油，也不能区分原油和成品油。需要航次货种时仍应连接船舶登记、
港口事件、提单或其他外部证据。

## 4. 位置筛选和质量控制

POS 解码后仅保留：

- `is_hard_valid=true`；
- MMSI 出现在年度油轮登记；
- 经度位于 -180–180、纬度位于 -90–90；
- 默认排除 `(0, 0)`。

输出保留原始行序号、接收时间、位置时间、航速、航向、导航状态、质量位掩码和登记元数据，便于追溯。

## 5. 三小时最近点

配置的八个目标时刻默认使用 UTC。对每个 `MMSI × target_time`：

1. 找出 `pos_time_s` 位于目标时刻 ±1800 秒内的候选；
2. 先按绝对时间差升序；
3. 并列时按位置时间、接收时间、源文件和原始行序号排序；
4. 选择第一条。

样本保留 `signed_offset_seconds`、`absolute_offset_seconds` 和 `candidate_count`。无候选时不插值、不补零。
午夜目标可能需要前一 UTC 日位置文件；缺失相邻分区时 manifest 会记录警告，若
`require_complete_window=true` 则直接停止。

当前 2025-07-15 单日样例没有 7 月 14 日位置分区，因此 UTC 00:00 的前半个容差窗口缺失；默认宽松模式会继续并记录警告。
正式结果应补齐相邻日位置，或在方法中明确这是单边窗口并单独评估偏差。

## 6. 热力图

DuckDB 先按配置的经纬度网格聚合，再把小型网格矩阵交给 matplotlib，避免把全年所有点装入内存。默认指标为
`sample_count`，颜色显示 `log(1 + count)`。也可将 `metric` 改为 `unique_vessels`。

该图用于流程验证和描述性探索，不是等面积统计图。跨纬度比较或论文制图应采用适当投影，并对网格面积、观察时长、
船舶数和缺测进行归一化。

## 7. 可恢复性和版本控制

每个阶段写 manifest，记录：

- 原始输入或上游输出的路径、大小和修改时间；
- 阶段参数；
- 程序版本；
- 输出签名、记录数、耗时和警告。

输出先写入唯一 `.partial-*` 文件，查询和计数成功后再原子替换正式文件。重复运行时，输入与阶段参数一致就跳过；
同时还会核对派生文件当前大小和修改时间是否与 manifest 一致。任一不一致则停止并要求显式 `--force`，避免
截断文件、新旧分类规则或不同登记版本被静默混用。

## 8. 当前已知限制

1. 内置解码器沿用既有实现，通信类型 2/3 的位置行没有映射 MMSI，因此不会进入油轮 JOIN。
2. 年度 `any_observed` 规则可能受 MMSI 重用、错误静态报文和年度内船舶属性变化影响。
3. 当前最近点法没有轨迹插值，稀疏或缺测船舶的八个时刻覆盖率会降低。
4. 单日样本无法验证全年季节性、空间偏差和异常日期。
5. CSV 不适合作为全年主存储；Parquet 才是正式中间成果。
6. 年度登记表更新会改变历史油轮集合；当前版本适合先冻结年度登记再批量处理，不适合每天追加后混用历史结果。

## 9. 建议验收指标

- doctor 所有项目通过；
- 小样本测试全部通过并生成 PNG/CSV；
- 正式日 STA/POS 文件大小与日期匹配；
- 登记表油轮数和船型冲突数合理；
- 每日位置记录数、MMSI 数、首末时间无异常；
- 八个目标小时覆盖率和时间偏差分布可解释；
- manifest 无未处理的边界、输入或磁盘警告；
- 重复运行全部跳过。
